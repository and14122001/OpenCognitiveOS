## PR #5 的正式 Linux 路徑

控制器在 worker 無法存取的目錄持有 SQLite、CAS、設定、規格及兩把獨立 32-byte 原始金鑰。設定檔包含 repo、workspaces、cas、policy_hash、controller_key_file、verifier_key_file。設定、金鑰及規格檔必須屬於控制器、使用 canonical 絕對路徑及私有權限。測試用公開金鑰只出現在跨 Runner 合成還原案例。

在 ExecutionAuthority 提交固定 Git SHA 的 TaskSpec 後、進入執行狀態前，以 register-acceptance 登錄獨立 AcceptanceSpec。其簽章同時涵蓋 TaskSpec 內容雜湊、權限、預算與驗收規格雜湊。早期草稿的舊簽章不能授權新執行。在模型推論與 OS 子程序之外的可信控制器持有狀態轉移能力。

The operator registers a private specification before dispatch. Supported native criteria are a fixed Git blob check, min_pass equal to one, and an optional explicitly approved single-file Python worker. Controller and verifier keys must be distinct. The worker receives a read-only script copy, isolated writable scratch, no credentials and no network. The configured authority requires sealed evidence even for a task that declares only mock tools.

下列為已建立 worktree、lease 後的命令介面。所有變數均取自同一控制器任務。complete-evidence 的原生工作紀錄由 broker 簽章決定。JSON 輸出參數供 CLI 相容使用。

```bash
opencognitiveos --db "$DB" register-acceptance --config "$CONFIG" --unique-key "$TASK" --spec "$SPEC"
opencognitiveos --db "$DB" run-approved-python --config "$CONFIG" --unique-key "$TASK" --worker "$WORKER" --execution "$EXECUTION" --epoch "$EPOCH" --workspace "$WORKSPACE" --script "$SCRIPT"
# The authority advances the leased task to VERIFYING before independent verification.
opencognitiveos --db "$DB" verify-file --config "$CONFIG" --unique-key "$TASK" --worker "$WORKER" --execution "$EXECUTION" --epoch "$EPOCH" --workspace "$WORKSPACE"
opencognitiveos --db "$DB" complete-evidence --config "$CONFIG" --unique-key "$TASK" --worker "$WORKER" --execution "$EXECUTION" --epoch "$EPOCH" --revision "$REVISION" --manifest "$MANIFEST" --output "$OUTPUT_JSON"
opencognitiveos --db "$DB" replay-evidence --config "$CONFIG" --unique-key "$TASK"
```
